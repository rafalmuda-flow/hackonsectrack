## Wynik, który oddajesz

Wynik pojedynczego agent run przechodzi schema/domain validation zanim stanie się artefaktem sprawy.

## Przeczytaj przed zmianą

`AGENTS.md`, `docs/01-PROCESS.md` (kroki P05, P06, P07, P08, P09, P10, P11, P13), `docs/04-ARCHITECTURE.md`, `docs/05-AGENTS.md`, `docs/06-UI-AND-OPERATIONS.md`, `contracts/`, `config/upstream.json` oraz właściwe upstream `AGENTS.md`. Jeśli kontrakt maszyny i tekst się rozjeżdża, zatrzymaj tylko tę kartę i zgłoś integratorowi konkretną różnicę; nie dodawaj alternatywnego endpointu. Współdzielony kontrakt zmienia jego właściciel przed startem równoległych kart.

## Wejście

agentId,input,tenantId,organizationId,userId,candidateId,expectedVersion; agentRuntime.run przez DI.

Scope `tenantId`, `organizationId`, `userId` pochodzi z auth hosta. Identyfikatory w URL/body są walidowane w tym scope. Daty mają format ISO8601UTC. Pole `expectedVersion` i `Idempotency-Key` są wymagane dla mutacji zgodnie ze specyfikacją API; odczyty nie zmieniają stanu.

## Wyjście i połączenie

AgentRun w OM i AcquisitionArtifact zproducer_agent_run_id,input_manifest,content_hash,schema_version,payload. Najpierw roleContracts[role].input.parse, potem inspectAgentInput(role,input). decision=needs_input zatrzymuje krok przed płatnym wywołaniem. Tylko decision=run uruchamia model. validateAgentOutput(role,input,output) działa przed zapisem przez CommandBus.

Kolejny konsument czyta wyłącznie zatwierdzony kontrakt/artefakt. Nie przekazuj wykonania przez kopiowanie tekstu między terminalami ani przez CSV jako bazę. Wynik błędny/niepełny zachowuje status `error`/`unknown`, zgodnie z konkretnym schema; nie zamieniaj ich na wynik negatywny `no`.

## Kryteria odbioru

1. Given poprawny wynik, When walidacja przechodzi, Then zapisuje się artifact i link do rzeczywistego AgentRun.
2. Given schema invalid lub nieistniejący evidenceRef, When agent skończy, Then brak zaakceptowanego artefaktu i jawny błąd output_validation_failed; native agent endpoint 422, własna malformed request 400.
3. Given scope case zmienił się lub expectedVersion nieaktualny, When zapisuję wynik, Then 409; wynik nie nadpisuje nowszego.
4. Given input nie ma wymaganych dowodów lub jest sprzeczny, When inspectAgentInput zwraca needs_input, Then zero wywołań modelu, zero zaakceptowanych artefaktów i konkretne reasons w interwencji człowieka.

## Przypadek negatywny i granice

Wywołanie engineering endpoint nie udaje workflow; HTTP200 nie zalicza kryteriów treści. Brak modelu 503 ma osobny status.

Nie budujemy w tej karcie discovery całego internetu, CRM/fulfillment, publikacji ani kampanii reklamowej. P1 nie jest warunkiem odbioru P0. Dozwolone działania konkretnej karty wynikają z jej zakresu, a nie z ogólnego zakresu skilla upstream.

## Jak sprawdzić

```bash
node --import tsx --test tests/acceptance/T13.test.ts
```

Ten plik testu jest **zadaniem do dostarczenia w tej karcie**. Na początku może nie istnieć: polecenie ma wtedy zakończyć się błędem, nigdy pominąć test jako sukces. Test obejmuje powyższe kryteria na rzeczywistej implementacji. Nie pisz testu sprawdzającego jedynie własny hardcoded fixture lub istnienie tekstu w specyfikacji. Dla UI użyj przeglądarki/hosta i zachowaj ręczny odbiór opisany niżej; screenshot bez sprawdzonego zachowania nie wystarcza. Dla pełnego OM testu wymagane są host+DB i zapisany run/record; mocki są tylko pomocą developmentową. W logu podaj dokładny tryb: portable, native harness, full OM host albo integrated demo.

## Demonstracja i dowód

Uruchom jeden krok przez native API/DI, odczytaj trwały AgentRun i artifact z bazy; odrzuć nieprawidłowy fixture output.

Zapisz w `evidence/tasks/T13.md`: commit/base SHA, wersję OM, datę, polecenie, wynik i istotny fragment logu/status HTTP, identyfikator użytego fixture, rzeczywiste run IDs (jeśli dotyczy), ścieżki zrzutów i jawne ograniczenia. Nie zapisuj sekretów, cookies ani cudzych danych. `npm run verify` jest kontrolą pakietu, a nie zamiennikiem odbioru powyższego zachowania.

## Dowód maszynowy i review Cezara

Format i polecenia w `docs/08-CEZAR.md`; nie wymyślaj hasha i nie podpisuj własnego review jako niezależnego.
