## Wynik, który oddajesz

Każdy wniosek można sprawdzić obok źródła, daty i ograniczeń.

## Przeczytaj przed zmianą

`AGENTS.md`, `docs/01-PROCESS.md` (kroki P03, P04, P05, P06, P07), `docs/04-ARCHITECTURE.md`, `docs/05-AGENTS.md`, `docs/06-UI-AND-OPERATIONS.md`, `contracts/`, `config/upstream.json` oraz właściwe upstream `AGENTS.md`. Jeśli kontrakt maszyny i tekst się rozjeżdża, zatrzymaj tylko tę kartę i zgłoś integratorowi konkretną różnicę; nie dodawaj alternatywnego endpointu. Współdzielony kontrakt zmienia jego właściciel przed startem równoległych kart.

## Wejście

GET /api/acquisition/candidates/:id; case detail DTO; artifact variants z kontraktów.

Scope `tenantId`, `organizationId`, `userId` pochodzi z auth hosta. Identyfikatory w URL/body są walidowane w tym scope. Daty mają format ISO8601UTC. Pole `expectedVersion` i `Idempotency-Key` są wymagane dla mutacji zgodnie ze specyfikacją API; odczyty nie zmieniają stanu.

## Wyjście i połączenie

Case detail z linkami dowodów, chronologią, coverage, fit i research; source text bez aktywnego HTML.

Kolejny konsument czyta wyłącznie zatwierdzony kontrakt/artefakt. Nie przekazuj wykonania przez kopiowanie tekstu między terminalami ani przez CSV jako bazę. Wynik błędny/niepełny zachowuje status `error`/`unknown`, zgodnie z konkretnym schema; nie zamieniaj ich na wynik negatywny `no`.

## Kryteria odbioru

1. Given diagnoza, When klikam evidenceRef, Then trafiam do właściwego źródła/fragmentu, nie tylko strony głównej.
2. Given partial feed, When czytam daty, Then tekst mówi ostatni zaobserwowany post, a nie ostatni opublikowany.
3. Given identity unknown, When chcę generować, Then widzę blokadę i możliwość potwierdzenia profilu z powodem.

## Przypadek negatywny i granice

Cudzy case 404 nie pokazuje nazwy; injection/HTML w materiale jest tekstem.

Nie budujemy w tej karcie discovery całego internetu, CRM/fulfillment, publikacji ani kampanii reklamowej. P1 nie jest warunkiem odbioru P0. Dozwolone działania konkretnej karty wynikają z jej zakresu, a nie z ogólnego zakresu skilla upstream.

## Poziom odbioru tej karty

Komponent działa wewnątrz hosta OM na jawnych fixtures odpowiadających dokładnie DTO. Ta karta odbiera renderowanie i interakcję, nie pełny przepływ backendu. Warstwa danych ma jeden adapter API, bez własnego business state. Podłączenie rzeczywistych endpointów i wspólny odbiór zapewnia T25 po scaleniu kart backendu. Raport nie może nazywać fixture pełną integracją.

## Jak sprawdzić

```bash
node --import tsx --test tests/acceptance/T16.test.ts
```

Ten plik testu jest **zadaniem do dostarczenia w tej karcie**. Na początku może nie istnieć: polecenie ma wtedy zakończyć się błędem, nigdy pominąć test jako sukces. Test obejmuje powyższe kryteria na rzeczywistej implementacji. Nie pisz testu sprawdzającego jedynie własny hardcoded fixture lub istnienie tekstu w specyfikacji. Dla UI użyj przeglądarki/hosta i zachowaj ręczny odbiór opisany niżej; screenshot bez sprawdzonego zachowania nie wystarcza. Dla pełnego OM testu wymagane są host+DB i zapisany run/record; mocki są tylko pomocą developmentową. W logu podaj dokładny tryb: portable, native harness, full OM host albo integrated demo.

## Demonstracja i dowód

Pokaż bad post, partial feed i błędną tożsamość. Popraw tożsamość ręcznie i pokaż zapis decyzji; API adapter można podłączyć po T08.

Zapisz w `evidence/tasks/T16.md`: commit/base SHA, wersję OM, datę, polecenie, wynik i istotny fragment logu/status HTTP, identyfikator użytego fixture, rzeczywiste run IDs (jeśli dotyczy), ścieżki zrzutów i jawne ograniczenia. Nie zapisuj sekretów, cookies ani cudzych danych. `npm run verify` jest kontrolą pakietu, a nie zamiennikiem odbioru powyższego zachowania.

## Dowód maszynowy i review Cezara

Poza raportemMarkdown dostarcz `evidence/tasks/T16.json` z `taskId`, `taskSpecHash`, `assertions:[{criterion,passed,evidence}]`, `limitations`. Każdy `criterion` jest dokładnym tekstem jednego kryterium z manifestu. Niezależny reviewer zapisuje `evidence/tasks/T16.review.json` z `taskId`, `taskSpecHash`, `verdict`, `findings`. Format i polecenia w `docs/08-CEZAR.md`; nie wymyślaj hasha i nie podpisuj własnego review jako niezależnego.
