## Wynik, który oddajesz

Demo kończy się jawnym lokalnym receipt i eksportem wejścia do przyszłej obsługi.

## Przeczytaj przed zmianą

`AGENTS.md`, `docs/01-PROCESS.md` (kroki P13, P14), `docs/04-ARCHITECTURE.md`, `docs/05-AGENTS.md`, `docs/06-UI-AND-OPERATIONS.md`, `contracts/`, `config/upstream.json` oraz właściwe upstream `AGENTS.md`. Jeśli kontrakt maszyny i tekst się rozjeżdża, zatrzymaj tylko tę kartę i zgłoś integratorowi konkretną różnicę; nie dodawaj alternatywnego endpointu. Współdzielony kontrakt zmienia jego właściciel przed startem równoległych kart.

## Wejście

POST /api/acquisition/candidates/:id/handoff {approvedArtifactId,approvedHash,target:"export",requestedNextStep}; Idempotency-Key; zatwierdzony bieżącyhash. GET /api/acquisition/candidates/:id/packet?artifactId=UUID.

Scope `tenantId`, `organizationId`, `userId` pochodzi z auth hosta. Identyfikatory w URL/body są walidowane w tym scope. Daty mają format ISO8601UTC. Pole `expectedVersion` i `Idempotency-Key` są wymagane dla mutacji zgodnie ze specyfikacją API; odczyty nie zmieniają stanu.

## Wyjście i połączenie

HandoffReceipt target=export,status=exported,target_record_id=null; JSON/HTML według acquisition.handoff.v1; w UI nie wysłano. accepted_by_agency jest niemożliwe bez rzeczywistego odbiorcy.

Kolejny konsument czyta wyłącznie zatwierdzony kontrakt/artefakt. Nie przekazuj wykonania przez kopiowanie tekstu między terminalami ani przez CSV jako bazę. Wynik błędny/niepełny zachowuje status `error`/`unknown`, zgodnie z konkretnym schema; nie zamieniaj ich na wynik negatywny `no`.

## Kryteria odbioru

1. Given zatwierdzony pack, When handoff dwa razy z tym samym key, Then jeden receipt i identyczny export.
2. Given brak approval albo zmieniony artifact, When handoff/export external pack, Then 409 stale lub 400 invalid i brak udawanej dostawy.
3. Given brak klientowskiej odpowiedzi, When eksportuję, Then outcome jest sales_handoff, nie won ani interested.

## Przypadek negatywny i granice

GET download także sprawdza tenant+org; nie uruchamiaj SMTP/DM/CRM write. Lokalny receipt nie jest potwierdzeniem odbiorcy. Dla oferty proposal lub niewygranej nowej próbki eksport ma requestedNextStep=internal_review i brak ceny.

Nie budujemy w tej karcie discovery całego internetu, CRM/fulfillment, publikacji ani kampanii reklamowej. P1 nie jest warunkiem odbioru P0. Dozwolone działania konkretnej karty wynikają z jej zakresu, a nie z ogólnego zakresu skilla upstream.

## Jak sprawdzić

```bash
node --import tsx --test tests/acceptance/T20.test.ts
```

Ten plik testu jest **zadaniem do dostarczenia w tej karcie**. Na początku może nie istnieć: polecenie ma wtedy zakończyć się błędem, nigdy pominąć test jako sukces. Test obejmuje powyższe kryteria na rzeczywistej implementacji. Nie pisz testu sprawdzającego jedynie własny hardcoded fixture lub istnienie tekstu w specyfikacji. Dla UI użyj przeglądarki/hosta i zachowaj ręczny odbiór opisany niżej; screenshot bez sprawdzonego zachowania nie wystarcza. Dla pełnego OM testu wymagane są host+DB i zapisany run/record; mocki są tylko pomocą developmentową. W logu podaj dokładny tryb: portable, native harness, full OM host albo integrated demo.

## Demonstracja i dowód

Kliknij eksport, otwórz JSON i pokaż recipient contract wraz z unknowns; log sieci nie zawiera wysyłki do klienta.

Zapisz w `evidence/tasks/T20.md`: commit/base SHA, wersję OM, datę, polecenie, wynik i istotny fragment logu/status HTTP, identyfikator użytego fixture, rzeczywiste run IDs (jeśli dotyczy), ścieżki zrzutów i jawne ograniczenia. Nie zapisuj sekretów, cookies ani cudzych danych. `npm run verify` jest kontrolą pakietu, a nie zamiennikiem odbioru powyższego zachowania.

## Dowód maszynowy i review Cezara

Poza raportemMarkdown dostarcz `evidence/tasks/T20.json` z `taskId`, `taskSpecHash`, `assertions:[{criterion,passed,evidence}]`, `limitations`. Każdy `criterion` jest dokładnym tekstem jednego kryterium z manifestu. Niezależny reviewer zapisuje `evidence/tasks/T20.review.json` z `taskId`, `taskSpecHash`, `verdict`, `findings`. Format i polecenia w `docs/08-CEZAR.md`; nie wymyślaj hasha i nie podpisuj własnego review jako niezależnego.
